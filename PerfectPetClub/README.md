# PerfectPetClub Customer Churn Analysis

## Project overview

This team data engineering project analyses customer subscription auto-renewal decisions for the fictional PerfectPetClub business. A JupyterLab ETL notebook combines data from a SQLite database and CSV files into a customer-level dataset stored as Parquet. A second notebook reads that dataset and visualises churn-related patterns with Matplotlib.

**Churn definition:** `churn = 1` when a customer's subscription has `auto_renew = 0`; `churn = 0` when `auto_renew = 1`. This measures disabled auto-renewal, not necessarily a completed cancellation.

## Data sources

The ETL uses these university-provided files, placed in the same folder as the ETL notebook:

- `PerfectPetClub.db` — SQLite database with customers, subscriptions, sales and related tables.
- `PerfectPetClub_CRM_report.csv` — customer service queries and complaints.
- `PerfectPetClub_server_log.csv` — web application login activity.
- `PerfectPetClub_survey.csv` — customer survey responses.

`PerfectPetClub_survey_questions.txt` documents the survey questions and can be consulted when interpreting survey fields.

The notebooks expect the CSV filenames shown above. If downloaded files have suffixes such as `(2)`, either rename the local files or update the `files` dictionary in the ETL notebook.

## How to run

1. Open JupyterLab in the project directory.
2. Confirm the four required data files are available locally and their names match the ETL notebook's `files` dictionary.
3. Open `PerfectPetClub_ETL.ipynb`, restart its kernel and run all cells in order.
4. Confirm that `output/PerfectPetClub_Churn.parquet` is created and the verification checks pass.
5. Open `PerfectPetClub_Dashboard.ipynb`, restart its kernel and run all cells in order.
6. Verify that all six charts appear, then export both executed notebooks to HTML with outputs included.

**Run the ETL notebook before the dashboard notebook.** The dashboard reads the Parquet file generated by the ETL.

## ETL process

**Extract:** Read the SQLite tables and CRM, server log and survey CSVs.

**Transform:** Standardise customer email addresses, clean subscription fields, join customer and subscription information, and engineer customer-level features including complaint counts, query counts, login activity, survey responses and sales activity. Remove selected unnecessary personal fields before export.

**Validate:** Check customer-level uniqueness, expected churn values, row counts and non-negative order counts.

**Load:** Save the analysis dataset to `output/PerfectPetClub_Churn.parquet` and read it back to verify the export.

## Dashboard

The Matplotlib notebook contains six charts:

1. Auto-renewal enabled versus disabled customer counts.
2. Disabled auto-renewal rate by subscription type.
3. Average customer complaints by churn group.
4. Average satisfaction score by churn group.
5. Average login activity by churn group.
6. Average order count by churn group.

These visualisations describe associations in the provided data; they do not establish causal relationships.

## Limitations and possible improvements

- The churn label indicates disabled auto-renewal, rather than confirmed customer departure.
- Some behavioural features may be unavailable for customers without matching source records.
- The analysis is descriptive and does not establish that complaints, satisfaction, logins or orders cause churn.
- Further improvements could include stronger join-coverage checks, explicit exception handling, automated tests and clearer chart interpretations.
